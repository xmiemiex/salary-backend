## 对应实现与证据

1. `sync-tasks/monthly-coverage.ts` 及 AW/PP/EF/CAKE 适配器：正式全来源完成后生成覆盖证明；`MonthlyFinanceService.status` 分开查正式最近任务和最近有证明成功。旧任务无证明不当作完整。
2. `SyncAutoExecutionService.pollDashboard` 短轮询领取后登记异步执行集合，不等待慢来源；数据库计数限制空位，同来源运行和候选互斥；worker 关闭时等待任务结束。
3. 同一执行器在领取前将最终过期 running 事务性终结并写审计；原刷新入口随后可以建立新批次。低于次数上限的过期租约仍恢复。
4. `ProviderCardInventoryService` + `20260905016000_resumable_inventory`：卡和持卡人分页进度持久化、固定终点、必要资料脱敏；完整 checkpoint 与进度清理同事务。达到三次失败后仍需用户单源重试，重试保留此前扫描进度。
5. `queriedAt` 为查询时间，`coveredThrough` 为来源证明的固定执行起点/历史月末；没有全部来源证明不显示共同截止时间。
6. `AdminLayout` 折叠配置/运维/权限，保留全部原入口。`DashboardPage` 固定核心五列，抽屉按来源每页20条服务端查询。汇总改为数据库 groupBy；两秒只查轻量状态，来源状态变化再更新汇总。
7. `prepare-monthly-finance-release.ps1` 要求干净提交和相同提交的浏览器证据，复制截图及哈希到候选目录。`browser-evidence.json` 记录 API/Web 构建树哈希和提交；最终提交及归档SHA以 `tmp/monthly-finance-release/manifest.json` 为准，旧209d2d7包不是本轮候选。
